# Android Architecture Design

Map current design before proposing changes. Define UI/domain/data/platform boundaries only where useful. Choose state, repositories, DI, persistence, and concurrency consistent with project conventions. Consider cancellation, offline behavior, migrations, and tests. Record significant tradeoffs in ADRs.
