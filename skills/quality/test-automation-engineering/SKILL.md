# Test Automation Engineering

## Workflow

Choose the test layer that gives reliable feedback at the lowest cost. Inspect framework and CI conventions before introducing new tools. Use stable selectors, fixtures, deterministic data, network isolation, and explicit cleanup. Avoid fixed sleeps, brittle implementation-detail assertions, shared mutable state, and tests that depend on public services. Cover success, validation, error, concurrency, and permission paths. Capture logs and artifacts on failure. Track flakiness separately from product failures and verify the suite in the same environment used for CI.

## Completion checks
- State what was inspected and what remains unknown.
- Keep the work within the user's scope and authorization.
- Preserve existing behavior and project conventions.
- Verify important changes with an observable check.
- Report evidence, caveats, and unverified areas separately.
